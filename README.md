# A Rubric-Based Framework for Assessing Software Test Coverage Quality of Large Language Models

## Overview

This repository accompanies the research paper:

**"A Rubric-Based Framework for Assessing Software Test Coverage Quality of Large Language Models Across Multiple Application Domains."**

This research introduces **SCOTC (Software Coverage and Test Completeness)**, a rubric-based evaluation framework for assessing the quality of software test cases generated by Large Language Models (LLMs) from Software Requirements Specifications (SRS).

Unlike traditional software testing metrics that depend on executable code, SCOTC evaluates requirement-level test generation through three quality dimensions: Completeness, Relevance, and Traceability. The framework also introduces a comprehensive error taxonomy to analyze common weaknesses in AI-generated software test cases.

---

## Abstract

Large Language Models (LLMs) are increasingly used to generate software test cases directly from natural language requirements. However, existing evaluation methods rely heavily on subjective human judgment or text similarity metrics, which cannot accurately measure software testing quality.

SCOTC provides a standardized evaluation framework that measures test quality using expert-defined rubrics and a structured error taxonomy. The framework was validated by evaluating eleven state-of-the-art LLMs across 180 functional requirements from nine different software domains.

The results show that while modern LLMs generate high-quality functional test cases, they continue to struggle with boundary conditions, negative scenarios, security validation, performance testing, and complex enterprise workflows.

# Evaluation Metrics

SCOTC evaluates each generated test suite using three quality dimensions.

| Metric | Description |
|---------|-------------|
| Completeness | Measures coverage of functional behavior, edge cases, boundary conditions, and exception handling |
| Relevance | Measures how well generated test cases align with the original software requirement |
| Traceability | Measures whether every generated test case can be directly traced back to the requirement |

Each dimension is scored on a five-point Likert scale.

The total quality score is calculated as:

```text
Total Score = Completeness + Relevance + Traceability
```

Maximum Score:

```text
15
```

Gold Standard Score:

```text
12
```

# Standard Evaluation Prompt

All models were evaluated using the same zero-shot prompt to ensure a fair comparison.

```text
You are a software test engineer.

Given a functional requirement from a Software Requirements Specification (SRS), generate a complete set of test scenarios.

Each test scenario must include:

- Test Scenario ID
- Scenario Description
- Preconditions
- Test Steps
- Expected Result

Ensure full functional coverage including positive, negative, and boundary cases where applicable.
Generate as many test scenarios as required for complete coverage.
```

SCOTC introduces twenty software testing error types grouped into seven categories:

- Original Errors
- Boundary Errors
- Structural Errors
- Data Errors
- Coverage Errors
- Traceability Errors
- Quality Errors

Common error types include:

- Missing Test Cases
- Missing Boundary Cases
- Missing Negative Test Cases
- Missing Security Scenarios
- Missing Performance Scenarios
- Incorrect Expected Results
- Missing Preconditions
- Traceability Gaps
- Duplicate Test Cases

# Key Findings

The experimental evaluation produced several important findings:

- GPT-4o achieved the highest overall performance.
- Claude 3.5 Sonnet and DeepSeek-V3 ranked closely behind GPT-4o.
- Commercial LLMs generally outperformed open-source models.
- Most models generated strong positive-path test cases but struggled with:
  - Boundary testing
  - Negative scenarios
  - Security testing
  - Performance testing
  - Complex enterprise workflows
- Model performance consistently declined as requirement complexity increased.
